# FR-10.9, assignments are not persisted

| ID | Requirement | |
|---|---|---|
| FR-10.9 | The map from name to assigned voice is held in memory only. A restart reassigns. | [D] |

Derived from FR-10.2 and FR-10.6, which are both satisfied whether the map
survives a restart or not.

The same argument as FR-3.6, reached independently. Losing the map costs one
reassignment per name, and the voices are equivalent by construction because our
user chose all of them by ear. Nothing on the shortlist is a worse outcome than
anything else on it.

**A restart can change what a name sounds like, and that is accepted.** It is
the one visible cost, and it is smaller than a file that can disagree with the
config it was derived from. A persisted map would also need a rule for what
happens when a voice it names is removed from the shortlist, which is a failure
mode that cannot occur if there is no file.

FR-10.3's release makes this cheaper still: the map is disposable by design,
since entries already expire.

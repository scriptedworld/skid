# FR-10.10, a declared name speaks in its declared voice

| ID | Requirement | |
|---|---|---|
| FR-10.10 | A name the config declares a voice for is spoken in that voice on every submission, however long it has been quiet. A name with no declaration is assigned one as FR-10.2 says. | [A] |

I asked for it as a hardcoded list: Ramona always uses one specific voice, and
so on for each agent. An agent's persona has a sex and a voice that contradicts
it is heard as somebody else.

A declaration is not an assignment that never expires. It is not in the
assignment table at all, so FR-10.3's release cannot touch it and FR-10.9's
restart cannot lose it, since the config is the record and is read again on
start.

skid infers nothing from a name. `af_` and `am_` in kokoro's ids encode sex, and
a name would be a guess at which to want; a member named against the grain is
exactly where the guess is wrong. The config says, and skid reads it.

`set_voice` is not the route. It is FR-6.1's single setting, the voice for every
caller with no assignment, and giving it a name argument would make one tool
mean two things.

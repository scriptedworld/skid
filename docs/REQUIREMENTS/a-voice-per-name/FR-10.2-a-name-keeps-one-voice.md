# FR-10.2, a name keeps one voice

| ID | Requirement | |
|---|---|---|
| FR-10.2 | Every submission is spoken in the voice assigned to its name. A name that keeps speaking keeps the same voice. | [A] |

Asked for first-hand 2026-08-30: a voice assigned to each session skid sees, so
who is speaking is carried by the sound as well as by the announced name.

**The key is the name, settled first-hand the same day:** *bound to name is
fine.* skid holds no session id and `resilience/40` removed the last one, so
binding to what `speak` already carries adds nothing a restart could make stale.

The consequence, stated rather than discovered: two sessions using one name
share a voice, always. That is right, because the name is the identity FR-3.1
and FR-3.2 already gave the listener.

**This does the same job as FR-3.2 by a second route**, and both stand. A
listener who has not learned the voices still gets the name.

# skid, Requirements

What must be true of voice output. Stated to me 2026-08-27 and recorded before
anything is designed, so the spec is derived from these rather than the reverse.

*Derives from:* stated requirements, first-hand. Nothing is built.

Requirements are stated as observable properties: what is true of a run, not how
anything is arranged.

**Status markers.** `[A]` traces to something I said. `[D]` is derived from one.
`[A/D]` is both. `[?]` is an open question, recorded so it is not lost and
carrying no test yet.

## FR-1, What it speaks with

| ID | Requirement | |
|---|---|---|
| FR-1.1 | Speech is generated by **kokoro**. | [A] |
| FR-1.2 | Generation produces an **audio file**. Nothing streams to a device from inside skid. | [A] |
| FR-1.3 | The file is played by running the operating system's audio player, or a user-defined one, as a **subprocess**. | [A] |
| FR-1.4 | Playback uses **the default output device**, whatever that currently is. skid does not select one. | [A] |
| FR-1.5 | **skid never talks to an audio device directly.** Device handling belongs to the player it invokes. | [A] |
| FR-1.6 | First pass targets **Linux only**. | [A] |

## FR-2, One at a time

| ID | Requirement | |
|---|---|---|
| FR-2.1 | **At most one clip is audible at any moment.** Two callers submitting at once produce sequential speech, never overlap. | [A] |
| FR-2.2 | Exclusion is held by a mutex, a lock file, or an equivalent. The mechanism is unconstrained; the property is not. | [A] |

## FR-3, Who is speaking

| ID | Requirement | |
|---|---|---|
| FR-3.1 | Every submission **carries a name** identifying the engine that sent it. | [A] |
| FR-3.2 | If a name's submission is the **first within `x` seconds** for that name, the spoken output is prefixed `Hi, [name] here.` | [A] |
| FR-3.3 | Later messages in the same chain are **not** prefixed. The prefix identifies a speaker, not a message. | [A] |
| FR-3.4 | `x` is configurable. Its default is unset. | [?] |

## FR-4, Submission shape

| ID | Requirement | |
|---|---|---|
| FR-4.1 | Text is submitted as an **array of messages**, not one at a time. | [A] |
| FR-4.2 | While one message is being spoken, **the rest are being prepared**. Generation and playback overlap. | [A] |
| FR-4.3 | Order is preserved: an array is spoken in the order given. | [D] |

## FR-5, Warm

| ID | Requirement | |
|---|---|---|
| FR-5.1 | A **backend process holds the model warm**, so a message does not pay model start-up before it is spoken. Wanted rather than required. | [A] |
| FR-5.2 | The client is an **MCP server**, reached through the standard Anthropic MCP SDK for Python. | [A] |

## FR-6, Voice selection

| ID | Requirement | |
|---|---|---|
| FR-6.1 | The voice is selectable **through an MCP tool**. | [A] |
| FR-6.2 | The voice is selectable **by editing the config file**. | [A] |
| FR-6.3 | Both routes reach the same setting. Neither is a separate copy. | [D] |

## FR-8, Saying it right

| ID | Requirement | |
|---|---|---|
| FR-8.1 | An **MCP tool declares patterns and their substitutions**, applied to the text before it is spoken. | [A] |
| FR-8.2 | The purpose is pronunciation: a word kokoro says wrongly is replaced by something that sounds right. The substitution is **heard, not read**, so it need not be a real spelling. | [A] |
| FR-8.3 | Substitution happens on the way to the engine and changes nothing a caller submitted or a log records. | [D] |

## FR-7, Open

| ID | Question | |
|---|---|---|
| FR-7.1 | Does a tool-set voice persist to the config file, or last only for the process? Two routes to one setting have to agree on which one is the record. | [?] |
| FR-7.2 | What happens to a submission arriving while another is playing: queue, reject, or replace? FR-2.1 forbids overlap and does not say which. | [?] |
| FR-7.3 | Does the lock cover generation as well as playback, or playback alone? FR-4.2 wants generation to overlap with speech, which means the lock cannot cover both. | [?] |
| FR-7.4 | What is `x` in FR-3.2? | [?] |
| FR-7.5 | Which player, and how is a user-defined one declared? `paplay` and `aplay` are present here; `ffplay`, `mpv` and `paplay`'s usual companions are not. | [?] |
| FR-7.6 | Is Python forced by kokoro, or chosen? kokoro has ONNX exports callable from other languages, so the model and the implementation language may be separable. Recorded because the first pass is Python by decision either way. | [?] |
| FR-7.7 | Are FR-8 substitutions literal or regular expressions? "Patterns" suggests the second, which brings ordering, overlap and a substitution matching its own output. | [?] |
| FR-7.8 | Do substitutions live in the config file as well as the tool, like the voice in FR-6? The same record question as FR-7.1 applies, and a pronunciation set is the more painful one to lose. | [?] |
| FR-7.9 | Are substitutions global or per name? A name identifies the submitting engine, and two engines may want the same word said differently. | [?] |
